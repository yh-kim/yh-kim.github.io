# 입력 포커스와 모션 수정

2026-10-19. Paper·Object·Frame 및 모든 컴포넌트 경로를 대상으로 수정했다. 기존 AI/프로젝트 대표 화면과 숨김 메모 가이드의 입력도 포함한다.

## 필수 입력 규칙

- 키보드 입력, 검색, textarea, select, 편집 가능한 영역은 포커스 전후 실제 글자를 16px 이상으로 렌더링한다. `--input-font-size: 16px`를 세 스타일·가이드·실행 HTML에 공유한다.
- 검색·필터·설정·복사용 코드 필드도 예외가 없다. 본문과 작은 라벨의 크기는 입력과 별도로 유지한다.
- `maximum-scale`, `user-scalable=no`, transform 축소를 사용하지 않는다. 사용자의 수동 확대는 유지한다.
- 각 스타일의 디자인 기준 첫 원칙과 `p/ui-motion/DESIGN.md`에 필수로 기록했다.

## 실제 재생

목록에 모션 버튼, 상세·독립 HTML에 다시 재생·일시정지/이어 재생·속도·초기화를 연결했다. 가이드 예제에도 모션 보기를 제공한다. 재생은 기존 상태를 초기화하는 버튼이 아니다.

탭은 다음 탭, 차트는 다른 기간, FAQ는 첫 답변, 표는 필터와 행 재배치, 캘린더는 가능한 날짜와 시간 목록으로 실제 상태가 변한다. 폼은 현재 값의 검증과 결과, 업로더는 파일 진행, 메뉴·드로어·확인창은 실제 열림을 시연한다. 자동으로 삭제·주문·예약을 확정하지 않는다. 세부 수치는 `siteRules`가 각 스타일 토큰과 컴포넌트의 기본 시간을 사용해 프롬프트에도 제공한다.

실행 중 속도를 바꿔도 현재 위치를 유지한다. 화면 밖·비활성 문서·사용자 일시정지는 같은 런타임에서 처리한다. 모션 감소 설정에서는 이동을 생략하고 결과를 유지한다.

## 확인

- 390×844: 세 스타일 폼의 이름·이메일, 검색·필터 select, 삭제 확인 입력, 복사용 textarea의 computed font-size 16px. 포커스 후 visual viewport scale 1, 문서 폭 390px을 확인했다. 기존 A 프롬프트와 B 정렬 select도 16px이다.
- 목록의 12개 모션 버튼을 실제 조작했다. 탭은 0.25× 재생을 중간에 정지해 패널 y=0.499887px가 유지되는 것을 확인하고 이어 재생했다. 모션 줄이기 후 다음 탭의 transform은 none이었다.
- 다운로드한 폼 HTML을 별도 URL에서 실행했다. 입력·동의 후 다시 재생으로 로컬 신청 완료를 확인했으며 콘솔 오류는 없었다.
- `node scripts/test-ui-motion-guide.mjs` 71개, `node scripts/test-ui-motion-showcase.mjs --require-full` 57개, `node scripts/test-ui-motion-styles.mjs` 14개 검사 통과.
- 구조·Daily URL·HTML 목록·본문 링크·개인정보 검사, Jekyll build와 빌드 결과 검사 통과. `scripts/verify-all.sh`는 저장소에 없어 개별 검사를 실행했다.

실기기 iOS 키보드는 연결되지 않았다. 모바일 크기의 실제 렌더링·포커스·배율과 확대를 유발하는 작은 입력 글자 제거를 검증했다. OS의 모션 감소 설정은 존중하며 강제로 해제하지 않는다.
