2026-10-19, [원본 갤러리](https://lucianlabs.dev/uxui-prompt/)의 애니메이션 컬렉션을 Chrome 1440×1000 뷰포트에서 확인했다. 13개 분류 필터로 ID와 분류를 대조하고, 갤러리를 끝까지 스크롤하며 201–300 카드 각각의 **실제 렌더링 화면을 봤다**. 숫자 검색으로 카드 27개를 직접 조작했다. 아래 `조작`은 실제 입력·클릭을 뜻하며, 화면 전후 변화가 불명확한 경우 따로 표시했다. 소스 설명만 읽고 렌더링으로 간주한 항목은 없다.

## 우리 12개 갤러리에 적용할 다섯 가지 교훈

1. **컴포넌트의 목적을 첫 화면만 보고 알 수 있어야 한다.** 230은 셔츠·가방·배송비가 있어 쿠폰의 뜻이 명확하고, 273은 고객 행과 상세 패널이 한 작업으로 이어진다. 우리 차트·태스크·필터의 반복되는 추상 지표와 장식용 설명을 실제 업무 데이터와 결정 지점으로 바꿔야 한다.
2. **움직임은 상태 변화의 경로를 보여 줘야 한다.** 201의 자동화 분기, 204의 버블 재집합, 292의 필터 뒤 카드 재배치는 각각 무엇이 어디로 갔는지를 설명한다. 우리 공통 fade/scale 버튼 반응만으로는 인터랙션의 원인을 알기 어렵다. 선택 전후 요소의 위치·계층·숫자가 연속적으로 변해야 한다.
3. **밀도와 위계는 목적에 따라 달라야 한다.** 202의 깊이 있는 데이터 그래픽, 230의 좁은 결제 요약, 273의 넓은 마스터·디테일, 297의 블록 작업대는 한 세트처럼 보이려고 평평해지지 않는다. 우리 모든 카드를 같은 크림색 평면·녹슨색 강조·큰 제목으로 정리한 접근은 다양한 사용 맥락을 잃었다.
4. **조작 뒤에는 작업 결과까지 보여 줘야 한다.** 209는 국가 선택에 번호 규칙을, 222는 별 수와 감사 문구를, 293은 담기 수와 비교표를, 297은 저장 상태와 실제 섹션을 함께 바꾼다. 우리 버튼들이 단순 활성색만 바꾸거나 결과가 카드 하단에서 잘리는 문제를 고쳐야 한다.
5. **좋은 데모는 자동 시연과 사용자 제어가 공존한다.** 213의 자동 탭, 227의 실시간 표, 284의 다단계 확인은 진행 중 상태가 읽히면서도 사용자가 직접 만질 수 있다. 우리 갤러리의 재생·일시정지 공통 도구만으로 각 컴포넌트 고유의 진행·취소·완료를 대신해서는 안 된다. 작은 카드 안에서도 핵심 결과와 조작이 끝까지 보여야 한다.

이 문서는 시각·행동 관찰이다. 원본 소스/에셋을 복제한 기록이 아니며, 후속 구현은 독립 작성 대상으로 둔다.
