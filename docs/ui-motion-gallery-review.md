# 컴포넌트 갤러리 개선과 검증


화면 캡처는 개인 로컬 보관소에 저장하며 저장소에는 포함하지 않는다.
2026-10-19. 커밋·푸시는 사용자의 추가 요청으로 승인됐다. 완성 화면을 다시 디자인하는 작업과 개별 컴포넌트 개선을 구분했다.

## 실제 위치와 시작 상태

- `/p/ui-motion/`는 컴포넌트 전체 목록이 아니라 완성 화면 두 개로 이동하는 허브였다.
- 개별 요소 목록은 `/p/ui-motion/ai-workspace/`, `/p/ui-motion/project-dashboard/`의 큰 대표 화면 아래에 나뉘어 있었다. 구현은 `js/ui-motion-showcase/index.js`, `data.js`, `engine.js`, `styles.css`였다.
- 원본 요소 정의는 `js/ui-motion-guide/themes.js`, 기본 런타임은 같은 폴더 `engine.js`에 있다. `/p/hidden-memo/ui-motion-guide/`는 Jekyll 글 안의 별도 보존 가이드다.
- 스택은 Jekyll + 네이티브 ES modules·Shadow DOM·dialog·WAAPI·IntersectionObserver. React·TypeScript·별도 앱 빌드 도구는 없다. 기존 검증 문서를 현재 전수 검사 증거로 사용하지 않았다.
- 원본 테마 정의는 요소 12개(2×6), 쇼케이스 카탈로그는 대표 화면 2개+요소 10개였다. 두 검토 다이얼로그만 카탈로그에서 빠져 있었다. 현재는 기존 12개 레코드의 ID·순서를 유지하고 두 다이얼로그를 뒤에 추가했다. 전체 14개 중 요소 12개를 새 갤러리에 표시한다.

배포 화면에서 차트 주간→누적, 완료 필터, 입력 오류를 먼저 직접 확인했다. 변경 전 모든 요소의 모든 상태를 조사했다고 주장하지 않는다. 변경 후 확인 범위는 아래와 인벤토리에 분리했다.

## 실제 구현과 두 차례 보정

`gallery.js/css`는 제목→검색/분류→결과→목록의 짧은 구조를 제공한다. 검색·분류·결과 없음·초기화·URL 쿼리가 실제 데이터에 연결된다. 카드 자체에 클릭 이동을 걸지 않고 별도 상세 링크를 사용한다. 자동 시연은 없으며 IntersectionObserver로 보이는 카드 주변 120px에서만 mount하고 화면 밖·숨김·상세창 뒤에서는 모션을 정지한다.

`component-design.js`는 대표 화면과 분리된 요소별 HTML/CSS를 제공한다. `engine.js`의 같은 markup·wire·CSS를 미리보기, 상세, 실행 HTML이 쓴다. 기존 장면·가이드 경로·해시는 그대로 유지했다. [DESIGN.md](../p/ui-motion/DESIGN.md)의 색·타입·간격·반경·모션을 실제 CSS와 토큰 명세에 반영했다.

첫 비교에서는 430px 카드에 380px 런타임이 들어가 하단 버튼이 잘렸고, 프리셋의 숨김 도구가 실제 화면에 큰 버튼으로 노출됐다. 카드 높이를 맞추고 중복 도구를 마크업에서 제거했다. 반복 영문 킥커도 제거했다. 다음 비교에서는 폼까지 전체 높이로 늘어나는 문제, 작은 보조 설명, 비슷한 두 검토창, 긴 현재 지시의 잘림을 수정했다. 마지막 모바일 조작에서 외부 모션 줄이기/속도가 내부 설정 필드가 없는 새 데모에 전달되지 않는 결함을 발견해 런타임 상태로 전달하도록 수정했다. 모달의 Tab 경계도 직접 순환하도록 보강했다.

## 실제 브라우저 검증

수정 요소 **12개**, 시각·조작 확인 요소 **12개**, 세 폭에서 미확인 요소 **0개**. 이는 모든 브라우저·모든 상태 조합을 완전 탐색했다는 뜻은 아니다. 대표 8개를 먼저 개선·검증하고 나머지 4개에도 공통 기준과 개별 표현을 적용했다. 기존 대표 화면 2개는 이 숫자에서 제외한다.

| 너비 | 실제 확인 |
| --- | --- |
| 1440×1000 | 12개 카드·상세, 생성 완료/취소, 레이어 재생, 프리셋 방향키, 차트 누적/막대/End/Escape, 작업 T-03, 완료 필터, 20일 빈 일정, 선택/disabled, 입력 오류/성공, 작업 추가/중복 오류, 두 모달 |
| 1180×900 | 2열 목록, 대표 8개 상태 변화 후 나머지 필터·선택·검토창 4개까지 조작. 상세 영역 의도하지 않은 가로 넘침 없음 |
| 390×844 | 1열 목록, 12개 상세, 긴 한국어 문장·제목, 터치 선택, 빈 일정, 모달 전체 화면/초점 복귀. OS 설정 대신 실제 ‘모션 줄이기’ 체크박스로 처리 즉시 100% 완료 확인 |

구체적인 상태 근거:

- 검색 없는 항목은 `0개 / 전체 12개`와 초기화 버튼을 표시. 입력 분류는 2개를 표시하고 초기화로 12개 복귀.
- 차트 누적값은 2/3/5/6. End로 19일 툴팁 `6개, 완료2/진행3/검토1`. Escape는 툴팁만 닫고 외부 상세창을 유지.
- 완료 필터는 총 2개·행 2개, 일정 20일은 0개. 작업 T-03 상세는 담당자 민서·검토 중.
- 폼은 빈 값 오류→유효한 긴 한국어 성공. 작업 추가는 7개→같은 제목 중복 오류→초기화 6개. 상세에서 추가한 행이 목록 미리보기에도 표시됨.
- 생성 중 실행 버튼 disabled, 취소 시 진행 0, 완료 시 100. 모션 줄이기는 즉시 완료. 0.25×에서 기본 처리보다 오래 진행된 뒤 완료되는 것까지 관찰했으며 정확한 프레임 시간 실측은 하지 않음.
- 두 내부 모달의 초기 초점·Escape·닫힌 뒤 열기 버튼 초점 복귀를 확인. 추가로 Shift+Tab은 마지막 취소 버튼, Tab은 첫 검토 완료 버튼으로 순환. 외부 상세를 닫으면 해당 카드의 상세 링크로 복귀.
- 실제 클립보드에서 실행 HTML을 다시 읽음. 차트·입력 HTML 두 개를 독립 URL에서 실행하고 상태 변화·콘솔 오류 없음 확인. prompt HTML 다운로드 이벤트가 실제 파일 경로를 반환함. 나머지 10개 실행 HTML은 구문/외부 의존성 자동 검사만 수행.

Chrome의 별도 시각 검토에서는 390px 모달 캡처가 페이지 스크롤값 약426px만큼 어긋나 보였다. 재확인한 computed position은 fixed, 모달/헤더 rect.top은 0, 실제 높이는844px, 조상 transform/filter는 none이었다. 따라서 그 캡처만으로 레이아웃 실패라고 판단하지 않았고 교차 브라우저 시각 판정에서 제외했다. 인앱 브라우저의 화면과 DOM은 정상 위치로 확인했다. 실제 모바일 기기·Safari·Firefox·스크린리더 낭독은 확인하지 않았다.

## 대비와 초기 부하

실제 CSS 색으로 계산한 대비: 본문/바탕 13.86:1, 갤러리 보조/바탕 5.50:1, 데모 보조/표면 5.19:1, 흰 글자/rust 버튼 5.54:1, 성공/표면 5.97:1, 오류/표면 6.85:1, 콘솔 글자/바탕 11.67:1. 작은 장식 경계선까지 모두 텍스트 대비 기준을 적용한 주장은 아니다. 조작 버튼·필터·입력은 최소44px, 검색/분류46px로 조정했다.

1440px 초기에는 6개, 1180px 4개, 390px 2개 카드만 mount된 것을 DOM에서 확인했다. 초기 자동 재생 타이머·WebGL·canvas·사진·웹폰트·새 라이브러리는 없다. 공유 엔진의 정적 모듈은 기존 대표 화면 코드도 함께 가져오므로 모든 불필요한 바이트를 제거한 것은 아니다. 네트워크 속도별 성능 점수나 실기기 프레임률을 실측하지 않았다.

## 출처·라이선스·남은 확인

[17개 참고 자료의 접근 수준과 라이선스](ui-motion-resource-audit.md)를 별도로 기록했다. React Bits 본문 등 접근 한계는 표시했다. 기존 MIT 고지는 실행 HTML에 보존했다. 신규 외부 소스·아이콘 패키지·폰트·사진·유료 자산을 추가하지 않았으며 자체 SVG 아이콘/CSS 도형을 사용했다. Unsplash 무료와 Unsplash+를 같은 조건으로 취급하지 않았다. 구매·가입·API 키 연결은 하지 않았다.

남은 검증: 독립 내보내기 10개 실제 실행, OS의 prefers-reduced-motion 설정 직접 전환, 스크린리더/실기기/Safari/Firefox, 대량 데이터와 매우 큰 집계 숫자의 레이아웃/성능. 기존 보존 가이드는 새 갤러리 런타임과 별개이며 이번에 다시 디자인하지 않았다.
