# Lucian UX/UI Prompt 101–200 실사 감사

- 기준: [Lucian UX/UI Prompt](https://lucianlabs.dev/uxui-prompt/)의 **인터페이스** 컬렉션, 2026-10-19.
- 범위: 101–200 총 100개. 이름·분류 100/100 확인; 실제 렌더 100/100 확인; 직접 조작의 상태 변화 34/100 확인.
- 방법: 네 분류(각 25개)를 차례로 열고 Chrome 1569×803 CSS px 화면에서 세 카드씩 한 행에 올려 36개 화면 캡처를 직접 확인했다. 그림·문자·조작부가 나타난 카드만 ‘렌더 ✓’로 표시했다. 조작 전후 텍스트, 수치, `aria-pressed`를 대조했다.
- 한계: 확대 화면은 표본만 열었다. 여섯 입력·키보드 시도는 자동화 초점 또는 값 갱신을 확인하지 못해 성공에 포함하지 않았다. 189·198은 진행 중 상태까지만 확인했다. 원본 코드·에셋은 구현에 복사하지 않았다.

## 현재 12개와 비교한 디자인·모션 격차

1. **각 카드의 주인공이 구별되지 않는다.** 참조 176은 타이포그래피 포스터와 버전 필름스트립, 200은 실물 영수증, 151은 기여 격자가 중심이다. 현재 12개는 같은 ARC 스피커, 같은 머리글, 같은 밝은 면을 여러 연구에 반복한다. 각 데모의 핵심 산출물이 첫 화면에서 바로 구별되도록 아트 디렉션을 나눠야 한다.
2. **무대의 깊이가 평평하다.** 참조 101·151·176은 항목별 색면, 내부 프레임, 그림자와 앞뒤 층으로 작은 카드에도 공간감을 만든다. 현재 갤러리는 모든 `.stage`에 `#ebece6` 배경과 얇은 테두리를 반복하고 컴포넌트도 크림/녹슨 빨강 토큰으로 일괄 처리해 소재 차이를 잃는다.
3. **모션이 상태를 따라 지속되지 않는다.** 참조 191은 재생 헤드가 폼 조작과 함께 진행하고, 193은 호흡 원형과 단계가 시간에 따라 바뀌며, 188은 공개 비율과 셀 채움이 연결된다. 현재 12개 중 다수는 정지 상태에서 클릭 뒤 단발 진입 애니메이션이나 성공 문구를 보여 준다. 무엇이 진행·변경 중인지 연속 상태로 드러나야 한다.
4. **430px 카드에서 조작부가 결과물을 압도한다.** 참조 116은 이징 곡선, 164는 분포, 170은 장애 그래프가 먼저 읽히고 조작은 주변에 모인다. 현재 컴팩트 카드에는 반복 머리글·설명과 44px 버튼 행이 자리해 제품 컷, 차트, 작업 목록이 상대적으로 작다. 카드에선 결과물을 크게, 정밀 제어는 확대 보기에 충분한 폭으로 배치해야 한다.
5. **입력의 결과가 약하다.** 참조 158의 비용 스위치는 그래프와 총합을 75→120으로 바꾸고, 164의 구간 선택은 막대 형태와 최빈값을 함께 바꾸며, 126은 문서 원문과 미리보기를 전환한다. 현재 `beam`은 선택 테두리, `layers`는 같은 층의 재생, `prompt`는 주로 상태 문구라서 행동의 결과를 시각적으로 판단하기 어렵다. 선택이 산출물의 구성·정보를 함께 갱신해야 한다.
