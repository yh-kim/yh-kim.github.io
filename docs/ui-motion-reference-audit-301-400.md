# Lucian UX/UI Prompt: rendered audit, IDs 301–400

## Scope and method

Reviewed the live [Lucian UX/UI Prompt collection](https://lucianlabs.dev/uxui-prompt/) in a dedicated Chrome tab. I selected “애니메이션 200,” scrolled the three-column gallery, and visually inspected overlapping viewport screenshots at 1440×1000. Every ID in this range appeared in at least one screenshot; the table describes the visible preview, not every possible animation frame. Titles and categories were cross-checked against a parsed catalog snapshot. I then used visible local demo controls across different interaction families. I did not submit web forms, buy anything, start a download, or request browser permissions.

**Coverage:** catalog inventory 100 / rendered previews observed 100 / demo control actions attempted 35; 30 produced a visible accessibility-state change and five attempts failed to resolve or complete. Most unlisted demos are marked visual-only; autoplay motion was not exhaustively tested per item. The search field sometimes lagged while filtering, and a custom color-filter control was not reachable through its advertised checkbox role, so that attempted sub-action is recorded as unsuccessful. No third-party assets or code were copied.

## Design lessons for our gallery

1. **Treat each preview as a miniature product surface.** The strongest demos give a specific object and context before motion: a 301 image comparison, 313 coffee order, 337 blossom map, and 393 platform download. Our gallery cards should show the actual component at usable scale rather than an abstract placeholder or a collection of labels.
2. **Let motion explain a relationship.** In 318 the route connects stops, 344 pins land on a map, 391 links departments, and 400 synchronizes a crosshair across metrics. Prefer one clear cause-and-effect gesture per demo over decorative ambient animation.
3. **Use depth and color where they carry meaning.** The warm drink/food cards, dusk landscape, layered map, 3D waffle blocks, and luminous data charts use color and depth to distinguish object, state, or hierarchy. Our restrained shared frame can remain consistent while individual demos use richer light, imagery, gradients, and dimensionality when the component benefits.
4. **Make the control part of the composition.** The better cards pair the visual with the control that changes it: 301 split/quality controls, 316 spring parameters, 361 slide navigation, 395 year selection, and 398 residual toggle. Put that control close to the result and show its current value/state.
5. **Keep small demos legible at card scale.** IDs 303, 326, 359, 387, and 398 make the data/text hierarchy visible without opening a detail view. Our previews need fewer tiny labels, larger focal content, and enough contrast to understand the state before a click.

These are evidence-based directions, not a mandate to reproduce Lucian’s dark gradient card frame. The implementation should keep our own gallery coherent while giving each demo a distinct, purpose-built visual and motion treatment.
