# 실사용 UI 갤러리 개편 검토 — 2026-10-19

## 수정 전 실제 화면에서 확인한 문제 5개

1. `/p/ui-motion/` 첫 진입은 여전히 두 대형 대표 화면의 허브였다. 사용자 요청의 컴포넌트 목록은 `/components/`에 따로 있어 실제 첫 화면의 탐색을 개선하지 못했다. `site-before-main-1280.jpg`에 두 대시보드와 별도 갤러리 진입을 기록했다.
2. 레이어·프리셋·선택 데모가 같은 스피커 그림을 반복했다. 웹사이트에 가져갈 입력·메뉴·가입·주문·예약 UI의 맥락이 없었다. 기존 소스와 이전 `revision-gallery-1440.jpg`, `revision-controls-1440.jpg`, `revision-layers-full-390.jpg` 기록으로 비교했다.
3. 테마 페이지의 카드 빈 영역 클릭을 상세 열기로 처리하는 코드가 남아 있었다. 목록 조작과 이동의 경계가 모호했다. 해당 fallback을 제거하고 명시적 자세히 보기 버튼만 남겼다.
4. 카드의 고정 높이와 compact 분기에서 기능을 숨겼다. 입력 결과·목록·컨트롤을 상세로 가야 볼 수 있었다. 새 런타임은 내용 높이를 사용하며 같은 기능을 목록·상세·HTML에서 실행한다.
5. 제목/영문 번호/설명을 안팎에 반복하고 동일한 둥근 흰 카드와 그림자로 감쌌다. 1180px 첫 구현을 본 뒤 내부 중복 설명·표면 그림자를 줄이고 폼·표·FAQ·차트·드로어의 구성을 구분했다. 새 가이드도 같은 실사용 UI 기준으로 바꿨다.

## 이번 범위와 보존

새 구현 12개. 삭제/숨김 없이 기존14개 카탈로그 ID·번호·두 대표 화면 경로를 유지했다. 메인과 components 경로는 같은 앱이다. 옛 가이드 경로는 디자인 기준을 열며 `#ui-THEME-KEY`를 현재 데모에 연결한다. 기존 이름은 legacyName으로 검색할 수 있다. 기존 대표 화면 자체의 전면 개편은 이번 범위에서 하지 않았다.

`site-catalog.js`에 목적·상태·키보드·모션·이전 이름을 연결했다. `site-inputs.js`6개와 `site-content.js`6개가 실제 기능을 담당한다. 메인은 가벼운 런타임을 직접 사용해 AI/프로젝트 대표 장면의 큰 모듈을 로드하지 않는다.

## 검증 집계와 한계

- 수정한 개별 데모: 12개. 메인 갤러리·상세·디자인 기준도 수정.
- 1440·390px: 각12개 목록 렌더링·주요 조작 확인. 세부 증거는 inputs/content/design QA 기록.
- 1180px: 루트가12개 목록의 주요 기능 조작. 저장, 잘못된 구독 폼/유효 제출, 설정 방향키/저장, 메뉴 복제, FAQ 두 답변 펼침, 태그 추가, 업로드 샘플/취소/재시도, 주문 빈 결과/초기화/일괄 처리, 예약 확정, 차트 기간/방향키, 장바구니 수량/합계/Escape/초점 복귀, 파일 이름 검증/삭제/실행 취소.
- 목록12개 시각 미검증 항목: 0개(위3폭). 모든 상태·OS·브라우저 조합을 완전 검증했다는 의미가 아니다.
- 보존한 대형 대표 화면2개: 기존 구현 유지. 새 디자인 품질 검증 집계에서 제외.
- 실제 이메일·업로드·결제·예약 API, 화면 읽기 프로그램, 실제 터치 하드웨어, Safari/Firefox 교차 검증은 하지 않았다. 예시 데이터를 실제 서비스 기능으로 보고하지 않는다.

검증 중 발견한 초점 문제도 수정했다. 업로드 진행에서는 버튼을 매 tick 다시 만들지 않는다. 장바구니 수량 변경은 같은 제어에 초점을 유지하고, 삭제 실행 취소 뒤에는 복구한 파일의 제어로 이동한다.
