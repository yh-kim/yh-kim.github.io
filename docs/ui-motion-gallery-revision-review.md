# 컴포넌트 갤러리 두 번째 개선·검증

2026-10-19. 이전 커밋 `1e1bb4e` 뒤의 후속 수정이다. 사용자 요청의 대상은 `/p/ui-motion/components/`와 개별 데모이며, AI Workspace·Project Dashboard 대표 장면을 갤러리로 오인하지 않았다. 기존 14개 ID·순서·경로를 유지하고 비대표 데모 12개를 수정했다. 항목을 줄이거나 숨겨 완료로 세지 않았다.

## 화면에서 확인한 부족함 다섯 가지

1. 목록 제목·설명과 데모 내부 제목·설명이 중복됐다. [수정 전 1440px](assets/ui-motion-gallery/revision-before-1440.jpg) 첫 세 카드에서 같은 설명 구조를 반복한다. 설명 제목을 제거하고 실제 제품 UI가 먼저 보이게 바꿨다.
2. 제품 예제가 작은 CSS 도형과 정지한 종이 묶음에 머물렀다. 자체 SVG 스피커를 만들고 제품/포스터·색·조명을 실제 결과에 연결했다. 레이어는 읽을 수 있는 세 층을 펼치고 다시 포갠다.
3. 차트·목록·일정·입력이 같은 종이색·강조색·카드와 작은 글자를 반복했다. 편집형 차트, 밀도 있는 인박스, 선 중심 필터, 보라 일정, 민트 입력, 따뜻한 승인 큐로 목적을 구분했다.
4. 상태 전환 대신 같은 등장 효과를 반복했다. 제품과 레이어는 현재 위치에서 반대로 이어지고, 필터는 이전 행 위치를 읽어 이동하며, 차트는 현재 높이에서 새 값으로 전환한다.
5. 빌드와 부분 조작만으로 전체 품질을 판단했다. 이번에는 모든 12개를 세 너비에서 렌더·조작하고, 미리보기와 상세를 별도로 확인했다. 전환·포커스·빈 상태·실행 파일을 따로 점검했다.

참고 사이트 400개의 이름·분류·렌더 관찰과 조작 시도의 차이는 [참고 감사 요약](ui-motion-reference-audit-summary.md)에 기록했다. 119개 카드/123회 조작 시도를 전체 400개 상호작용 검증으로 표현하지 않는다. 001–100의 개별 시각 메모가 상대적으로 약한 점과 실패·미확인 시도도 그대로 남겼다.

## 구현과 항목별 확인

각 링크의 기본 경로는 `/p/ui-motion/components/`다. 1440px·390px에서는 10개 데모의 compact 미리보기와 주요 조작을 개별 검토했고, 처리·제품 검토는 전체 화면에서도 검토했다. 1180px에서는 12개 full 데모를 순회하며 아래 동작을 실행했다. 이후 390px full 12개도 추가로 렌더링해 연락판으로 비교하고 입력·선택의 모바일 구도를 다시 수정했다.

**수정 12개 / 실제 시각 확인 12개 / 현재 갤러리의 렌더 미검증 0개.** 모든 상태·브라우저 조합을 전수 검증했다는 뜻은 아니다. 기존 대표 장면 2개는 신규 디자인 대상에서 제외했으며, 컴포넌트 CSS가 대표 장면으로 새지 않는 회귀 검사를 추가했다. AI 장면의 배경 `rgb(6,13,25)`와 기존 `/project-dashboard/#light-project--filters` 상세 열림을 브라우저에서 확인했다.

## 비교 후 다시 고친 부분

- 첫 수정본에서 처리 큐의 세로 단계가 compact 430px을 넘어 버튼을 잘랐다. compact 단계만 가로로 바꾸고 버튼·진행률을 카드 안으로 복구했다.
- 차트 하단 필터가 잘리는 문제를 발견해 compact 플롯 높이를 조정했다. 필터를 없애지 않았다.
- 펼친 레이어의 세 장이 겹쳐 정보를 가렸다. compact에서 70px 높이의 읽을 수 있는 세 줄로 이어지게 바꿨다.
- full 호스트가 미리보기용 100% 높이를 상속해 상세 하단에 빈 공간을 만들고 조작을 밀었다. 호스트를 내용 높이로 바꾸고 실제 높이를 재측정했다.
- [모바일 입력 상세의 첫 상태](assets/ui-motion-gallery/revision-prompt-mobile-iteration.jpg)는 두 열 때문에 문장이 잘게 끊겼다. [세로 재배치 후](assets/ui-motion-gallery/revision-prompt-full-390.jpg)는 150px 입력창과 적용 결과를 위아래로 둔다.
- 390px full 선택 데모의 제목·보조 문장 겹침을 발견했다. 내부 여백과 제어 레일 폭을 바꾸고 [세 영역 이동](assets/ui-motion-gallery/revision-beam-full-390.jpg)을 다시 확인했다. 제품 정보처럼 보이던 장식도 실제 펼침 버튼으로 바꿨다.
- 저장된 상세 상태가 이후 카드 수정을 덮는 버그를 고쳤다. 상세 방문→닫기→카드 제품 컷 선택→재열기의 실제 브라우저 순서에서 최신 카드 선택 보존을 확인했다.
- 보조 글자 대비를 계산했다. 예: 흰 바탕 `#7890a6` 3.31:1을 `#5d7288` 4.97:1로, 민트 바탕 `#709783` 2.81:1을 `#4f735f` 4.58:1로 수정했다. 전체 접근성 인증을 수행했다는 뜻은 아니다.

## 재사용·부하·권리

새 라이브러리, 외부 폰트, 사진, API 연결, 유료 구매, 가입은 없다. 새 제품 SVG/CSS와 데모 코드는 독립 작성했다. 기존 대표 장면의 Lucian #280 노이즈 MIT 고지는 해당 장면의 실행 HTML에 보존했다. 다른 사이트의 코드·개별 기여자 컴포넌트·Unsplash/Unsplash+ 자산을 재사용하지 않았다. 사이트별 접근 한계와 라이선스 조건은 [리소스 감사](ui-motion-resource-audit.md)를 유지한다.

필요한 카드만 120px 전부터 mount하고 자동 시연은 하지 않는다. 화면 밖·문서 숨김·상세 뒤의 WAAPI 작업을 중지한다. CSS는 사용자 입력에 따른 유한 상태 전환이다. WebGL/캔버스·외부 이미지·웹폰트 요청은 없다. export는 관련 데모 계열 CSS만 포함하도록 분리해 약 58.6–86.2KB 단일 HTML이다. 미리보기/상세/export의 마크업·wire·enhancer 원본은 같다.

12개 실행 HTML을 실제 별도 로컬 서버에서 열어 재생/선택/입력 오류/작업 추가/검토 열림을 확인했다. 실행 코드 복사 후 완료 문구와 클립보드 문자열 일치를 확인했다. 검색 0건·분류 2건·초기화도 실제 데이터와 연결됨을 확인했다. 앱 콘솔 오류·경고는 검증 탭에서 발견되지 않았다.

- `scripts/verify-all.sh`: 구조, Daily URL, HTML 목록, 로컬 링크 272개, Jekyll build, 빌드 산출물, 개인정보 검사 통과.
- `ruby scripts/test-harness.rb`: 통과.
- `git diff --check`: 통과.

별도 TypeScript/ESLint 구성이 없는 정적 JavaScript 프로젝트이므로 해당 이름의 검사는 제공하지 않는다. 실제 휴대폰·터치 장치, Safari/Firefox, 스크린리더, 모든 빠른 클릭 조합, 정량 Core Web Vitals는 미검증이다. 데스크톱 브라우저의 실제 viewport 1440/1180/390px 렌더·입력 확인과 구분한다. 참고 400개 중 직접 조작하지 않은 281개와 실패·불명확한 시도는 감사 문서에 남겼으며, 현재 갤러리에 가져와 완성한 것으로 세지 않았다.

작업 분담은 Hermes 절차에 따라 Sol/high 두 명(제품·데이터 데모)과 Luna/medium 한 명(참고 관찰·독립 상태 검토)을 사용했다. 최종 통합·1180px 전 항목 조작·모바일 full 전 항목 비교·회귀 수정은 주 에이전트가 수행했다. 커밋·푸시는 앞서 받은 명시적 승인 범위로 진행한다.
